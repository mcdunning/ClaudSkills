This repository contains four Claude Code skills, `new-project`, `start-feature`, `open-pr` and `merge-pr`, plus `install.sh` and a plain-bash test suite. They implement the user's project setup and git workflow: `main` and `develop` branches, feature branches named `feature/<slug>` off `develop`, squash merges, and a human approval before every commit or merge to `main` or `develop`. The project was set up with its own `new-project` procedure: the GitHub repository mcdunning/ClaudSkills is public, `main` and `develop` are pushed and protected (`main` strict, `develop` with admin bypass), and all skill work is on branch `feature/skills-build`, awaiting a pull request into `develop`. `bash tests/run.sh` passes with no failures.

Skills live in `skills/<name>/` with scripts in `scripts/` and exact-copy files in `templates/`; tests are in `tests/`; designs are in `docs/superpowers/specs/` and plans in `docs/superpowers/plans/`. Do not call real GitHub from tests, which use a stub `gh` that logs one argument per line. Real `gh pr merge --delete-branch` force-deletes the local branch, so `merge-pr` does not pass that flag and deletes the remote branch with `git push origin --delete` instead. Do not rewrite or edit an existing `CLAUDE.md` in a user's project; the skills only append missing sections. Branch protection requires a pull request but zero approving reviews, because the owner cannot approve their own pull request on GitHub; the approval is the user's go-ahead in the session.

Open items: step 3 of `skills/new-project/SKILL.md` moves `main` with `git branch -f main develop`, which is not a fast-forward and can rewind `main` in an existing repository where `main` has commits that `develop` lacks; it should check `git merge-base --is-ancestor main develop` and use `git merge --ff-only` instead. The `release` skill (version bump, tagging, changelog, `develop` to `main` merge) has a design outline but is not built. The skills are not installed into `~/.claude/skills/` yet, and no manual smoke test of them against real GitHub has been run; `install.sh` was verified only against a temporary directory. Deferred minor items are an existing-PR check in `open-pr`, inconsistent exec bits on scripts, and duplicated test helpers.
